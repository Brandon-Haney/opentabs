# Where PowerPoint live editing stands — 2026-09-03

A snapshot of one working session, written so the next one does not have to
reconstruct it. Companion to [[live-editing-suite-plan.md]] (the forward plan),
[[pods-action-catalog.md]] (the decoded wire) and [[microsoft-office-web-apps.md]]
(the cross-app field guide).

## What prompted it

Three complaints about editing a real deck, all correct:

1. A deck shared from another company could not be touched at all.
2. Formatting was all-or-nothing — changing a few words flattened the paragraph.
3. There was no way to insert a hyperlink.

All three are now answered, two by shipping and one by a diagnosis that turned out
to be the opposite of what everyone assumed.

## Shipped

**Formatting a range.** `format_text` and `set_font_size` take an optional `match`
(with `occurrence`), so an agent formats part of a paragraph the way a person
selects a few words and clicks Bold. Text outside the match keeps what it had, a
match spanning two formats keeps both bases, and a paragraph that already carried
several runs is no longer refused. Live-verified: one word of the test deck's title
turned red and back, `applied: true` both ways.

**Hyperlinks, both directions.** `set_hyperlink` links a stretch of a paragraph and
`remove: true` takes the link off. Live round-tripped: add then remove returns the
title to its original text and colour.

**Identity-aware auth.** `diagnose` reports whether the page is a tenant member, a
B2B guest, or an anonymous sharing-link visitor, and whether the host opened the
file for editing. Graph calls on an anonymous-link page fail as
`ANONYMOUS_SHARING_LINK` naming the live tools that do work there, and
`reauthenticate` skips instead of reloading — a reload would only drop the one
session that functions.

**A real expiry for sniffed tokens.** A Graph bearer read off a request header was
trusted for a flat ten minutes regardless of its actual lifetime, so a token good
for an hour started failing after ten. It now keeps the JWT's own expiry.

**The capture channel grew up.** The in-frame write log holds sixty writes instead
of twelve, bounded by bytes as well as count, and answers as a manifest that names
each write by its own action name, with bodies pulled individually by index. It
reports what it had to drop. Both write sentinels stopped returning the session
headers — a decode only ever needs the body.

**Platform diagnosis plumbing** (from earlier uncommitted work, reviewed and
landed): structured failure detail carried from a plugin to the audit log, tab
attribution recorded as an origin, and a retry wrapper with a per-call-site
idempotency policy.

## What we learned

**Anonymous sharing links have no Microsoft 365 identity.** The earlier reading —
"the plugin authenticates against the home tenant so it cannot reach another
company's deck" — was wrong. Such a page runs as `urn:spo:tenantanon` with no MSAL
and no AAD user, so nothing ever mints a Graph token and nothing can refresh one.
The WOPI editor session is fully live, so the co-authoring tools work normally. The
transport was never the problem; the identity was.

**How a paragraph holds more than one format.** The text is one string. Runs carry
formatting and no text. `469769746` holds the boundary offsets, `603987475` one run
reference per stretch, and the same run object is reused across stretches. Bolding
one word leaves the head and tail pointing at the original run.

**A hyperlink is a Word field code in the text**, hidden by run flags — no
relationship, no run property. See the catalog.

**Omission means unchanged, not off.** A revision is merged onto the document, so a
property a write leaves out keeps the value it had. A constructed link removal that
deleted the field flags instead of writing them `false` left the run half a field,
and the editor repaired it by rebuilding the link with a target guessed from the
visible words. This is the single most transferable thing learned here.

**Our writes cannot be undone by the user.** They arrive through the co-authoring
channel as a collaborator's edit, so the editor's own Undo does not touch them.
Every destructive live action needs a programmatic inverse or it is one-way.

**The client hands over its own vocabulary.** An unauthenticated `GET` of
`usc-powerpoint.officeapps.live.com/pods/ppt.aspx` returns the real editor shell,
and its bundles are public CDN assets. From them: 2,892 action names with ids, and
2,195 property ids with types, validated against every id the repo had decoded by
hand. Kept at `~/.opentabs/wire-catalogs/`. What it does **not** give is which
objects an action's revision must carry — the client has no per-action builder, it
diffs two document snapshots and serializes whatever came back dirty. That is why
captures remain necessary for the object graph, and only for the object graph.

**PowerPoint creates only seventeen object types.** A direct count of every literal
`createInstance` across all bundles. The structural surface is finite and mostly
already proven.

## Also fixed along the way

- `align_text`'s justify emitted an action name that exists nowhere in the client.
- The error sanitizer mangled Microsoft's own proxy labels into nonsense, and its
  replacement then redacted clock times. Both corrected, with tests.
- Two SDK docs promised that error details reach the agent when a test enforces
  that they do not.
- The field guide's claim that the wire format is absent from the client JS, which
  is false and would cost the next reader the whole static-analysis route.
- The network capture now redacts the Office session tokens, whose header names its
  allow-list spelled differently.

## The state of the tree

Six commits, five pushed. The sixth (hyperlinks) is committed locally and blocked
by an unrelated pre-push failure, described below.

Around 150 non-lockfile files remain uncommitted from a prior session: the Microsoft
plugin rollout across Excel, Outlook, Word, Teams and OneNote, plus documentation
and end-to-end changes. All of it was reviewed this session and passes every gate;
it needs the small fixes listed below rather than rework.

## Gameplan

### 1. Unblock the push

The create-plugin scaffolding test runs a real `npm install` plus build and lint
against a 180-second budget and is taking over 400 on this machine. It is unrelated
to the change and fails the same way alone. Not memory, not the registry, not stray
processes — Windows Defender realtime scanning is the remaining suspect, and the
test sits right at the edge of its budget. Either raise its timeout, which its own
CI-skip comment already concedes is warranted, or push this once with the hook
skipped.

### 2. Paragraph creation

`NewLine` is decoded and unbuilt: two chained revisions in one POST, appending a new
text-body block to the shape rather than a paragraph to the existing one. This is
what turns a four-paragraph template into the thirty-nine a real review needs, and
it is the last piece of the original request.

### 3. End-to-end tests on Windows

735 tests already pass here. Three defects stand between that and a full run: the
npm script's POSIX shell syntax, a signal the test helper cannot send on Windows,
and a `pgrep` call in one spec. The signal fix removes a platform branch rather than
adding one — the proxy already watches its dist directory, so the helper can touch a
file instead.

### 4. Land the Microsoft plugin work

Needs, in order: an `If-Match` guard on Word's full-file PUT, which is now a written
policy violation and is made repeatable by the retry this change adds; one
inconsistent option name; a fingerprint helper duplicated six times that belongs in
the shared manifest; and four green tests for a build flag that no longer exists.
Three things should be deleted rather than committed — the PR-drafts folder with its
deck screenshots, a stray userscript, and an accidental `file:..` line that breaks
the docs check.

### 5. The autonomous capture loop

The highest-leverage item. The editor exposes its action manager in the frame our
pre-script already occupies, so a script can ask whether an action applies, fire it,
let the interceptor record the write, and undo. That removes the human from every
future capture. Build it before spending the nine remaining structural captures, not
after. Roughly two hundred further actions are a single property on a single node —
a shape already shipped twice — and need no capture at all once an offline validator
exists.

### 6. Standing debt worth naming

Graph tokens still die after about an hour with no silent refresh, so
`reauthenticate` remains a routine cost. Our class constants are misnamed in a way
that misleads: what the code calls a text run is really a shared style object. The
staged file-rewrite tools are still scheduled for retirement. And none of the other
Microsoft plugins know about the anonymous-link case, so a shared file still gives
the same bare "not authenticated" that started this session.
